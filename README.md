# Greek Language Course (PWA)

A **zero-dependency, offline-first, static** Progressive Web App for learning
Modern Greek. Lessons are authored in Markdown, compiled to HTML by a Python build
step, and served as a vanilla-JS single-page app. Deployed on Cloudflare.

No runtime framework, no bundler, no client-side packages. The only build-time
dependency is the `markdown` library (`requirements.txt`).

## Quick start

Requires Python 3. The build is pure Python, so Node is optional — the `npm run`
commands below are thin aliases for the `python3` invocations shown in comments.

```bash
# Build content + assets into dist/
npm run build        # = pip install -r requirements.txt && python3 scripts/build.py

# Serve locally at http://localhost:8002
npm run serve        # python3 scripts/serve.py

# Build then serve
npm run dev
```

`dist/` is generated by the build and is **not** committed — it is rebuilt fresh
for every deploy.

## Project layout

```
data/el/          Course content (Markdown lessons + curriculum.json index)
src/              App source: index.html shell, js/ modules, css/, sw.js
assets/           Icons and lesson illustrations
scripts/          build.py (compile) and serve.py (local dev server)
docs/             Documentation (see below)
dist/             Build output (generated, gitignored)
```

## Authoring a lesson (at a glance)

Lessons are Markdown under `data/el/lessons/{grammar,vocabulary,practice}/`. The
filename stem is the lesson `id` referenced in `data/el/curriculum.json`. Beyond
standard Markdown, the build supports `> [!NOTE]` / `[!TIP]` callouts,
`::: reading-segment … ::: end` blocks, and JS-free `<details>` "Quick Check"
self-tests. Every `curriculum.json` id must have a matching file, and vice versa.
See [docs/authoring.md](docs/authoring.md) for the full conventions.

## Deploy (at a glance)

Cloudflare Pages is connected to the repo and **builds + deploys on every push to
`master`** — there is no deploy step or secret in this repo. Separately,
`.github/workflows/ci.yml` validates the build (integrity check + compile) so
breakage is caught before Cloudflare builds. The service-worker cache version is
stamped from a content hash at build time, so deploys invalidate stale caches with
no manual version bump. See [docs/deploy.md](docs/deploy.md).
